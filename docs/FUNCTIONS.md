# 함수·재귀와 반복 비교 계약

그래프 탐색 이후 사용자의 ‘이어서 진행’ 요청에 따라 1차 MVP의 함수 학습 범위를 보완했습니다. 일반 함수와 변수 범위, 팩토리얼·피보나치, 재귀·반복 비교를 추가했습니다. 메모이제이션·동적 테이블·하노이 탑 등 다른 예제는 별도 확장입니다.

## 사용 방법과 예제

**함수와 재귀 → 예제 선택 → 실행 방식·입력 → 입력 적용** 순서로 준비합니다. 입력, 예제, 방식, 한도를 바꾸면 재생과 기존 기록·비교를 초기화합니다. 입력 범위가 다른 예제를 선택하면 그 예제의 기본값으로 바뀌고 입력 적용을 기다립니다.

| 예제                       | 정의·입력             | 관찰 목표                                               |
| -------------------------- | --------------------- | ------------------------------------------------------- |
| 1부터 n까지의 합           | n=0–12, sum_to(0)=0   | 호출·복귀와 누적 덧셈, 같은 문제의 반복 구현            |
| 팩토리얼                   | n=0–12, 0!=1          | 종료 조건 1과 곱셈 반환, 반복 누적                      |
| 피보나치                   | n=0–8, F₀=0, F₁=1     | n−2 호출 후 n−1 호출, left/right의 독립된 값, 다중 호출 |
| 지역·전역 변수와 함수 호출 | n=0–12, 전역 total=10 | 값 전달·지역 변경·global 변경·None 반환과 중첩 호출     |

모두 교과 개념을 바탕으로 새로 구성한 읽기 전용 Python 예제입니다. 각 예제에 정의·학습 목표·관찰 질문·설명·비교·재적용 활동을 제공합니다. 학생 답변을 수집하거나 채점하지 않습니다.

### 변수 범위 예제

`process(n)`이 `local_add(total,n)`과 `add_to_total(n)`을 차례로 호출합니다.

- local_add의 total은 전달된 값으로 시작하는 **매개 변수**입니다. subtotal을 계산한 뒤 이 total에 대입해도 전역 total은 바뀌지 않습니다.
- local_add가 반환한 수를 process의 preview에 저장합니다. 반환 직후와 대입 완료를 별도 Step으로 관찰합니다.
- add_to_total의 global 선언은 total이 전역 변수를 가리킴을 설명합니다. 선언 자체는 대입·연산량에 포함하지 않습니다.
- 이어지는 전역 total 대입은 공유된 전역 값만 바꿉니다. 지역 함수 호출은 값을 복사해 전달받은 정수 예제이며 가변 객체의 참조 전달을 다루지 않습니다.
- 명시적 빈 return은 None을 반환합니다. process의 receipt는 호출 전 ‘아직 없음’, 반환 뒤의 대입에서 ‘None · 반환값 없음’이 됩니다.
- process는 preview를 반환하고 최종 전역 result에 대입합니다. n=4이면 전역 total과 result는 14입니다. 함수 호출은 총 3회, 동시 프레임은 최대 2개입니다.

호출 트리와 콜 스택의 함수 표기는 호출 시점의 인수를 보존합니다. 콜 스택은 이를 ‘호출 당시 인수’로 명시하고 현재 매개 변수를 이름=값 형식으로 별도 표시합니다. n=4의 6단계에서는 두 그림 모두 local_add(10, 4), 현재 매개 변수 total=14이며 전역 total=10입니다. 이 예제는 범위 차이를 관찰하기 위한 것입니다.

## 실행기와 Step

`engine/function-trace.ts`는 제한된 예제들이 공유하는 기록 도구입니다. 함수 진입·복귀, 전역/지역/매개 변수 대입, 비교, 깊이 한도와 호출 관계를 기록합니다. 코드 문자열을 해석하거나 평가하지 않습니다. 기존 재귀 합 실행기는 그대로 재사용하고, 새 예제와 반복 구현은 `examples/functions.ts`가 표시 코드·줄 매핑·실제 연산을 함께 정의합니다.

모든 Step은 사건 **후** 상태입니다. 호출마다 새 프레임과 고유 ID를 만들며 부모 호출은 반환 대기로 바뀝니다. 반환 사건에서 자식을 제거하고 부모를 활성화한 뒤, 제거 ID·반환값·복귀 위치를 returnInfo에 보존합니다. 그 다음 대입 사건에서 호출 결과를 지역/전역 변수에 저장합니다. 함수 정의는 준비 상태에 포함하며 실행 중 비용으로 세지 않습니다.

scope 사건은 global 선언의 범위를 설명합니다. `iterations`는 반복 몸체의 첫 대입을 실행한 횟수이며 다른 모듈에 적용되지 않으면 생략합니다. 호출 트리·변수·스택·코드·기록·분석은 같은 불변 Step을 사용합니다.

### 재귀와 반복

피보나치 재귀는 먼저 fib(n−2)를 끝까지 계산해 left에 저장한 뒤 fib(n−1)을 계산해 right에 저장합니다. F₀=0, F₁=1이며 n≤1에서 n을 반환합니다. 같은 인수의 호출도 고유 프레임·호출 노드로 남깁니다. 캐시 적중이나 중복 계산 제거를 구현한 것은 아닙니다.

합·팩토리얼 반복은 total을 각각 0·1로 초기화하고 i=1부터 i≤n 동안 누적합니다. 피보나치 반복은 a=0, b=1, i=0에서 시작해 i<n 동안 next_value=a+b, a=b, b=next_value, i=i+1을 순서대로 수행하고 a를 반환합니다. 덮어쓰기 전 값을 next_value에 남겨 각 대입을 관찰합니다.

학습 목표·예상 질문·관찰 변수·설명·재적용 활동은 실행 방식별로 정의합니다. `getFunctionLesson`이 선택한 방식의 안내를 반환하며 비교 과정 전환에도 함께 바뀝니다. 반복 피보나치에서는 a·b·i·next_value를 관찰하고, 재귀 피보나치에서는 left·right와 호출 순서를 관찰합니다.

## 비교와 지표

**같은 입력으로 재귀·반복 비교**를 누르면 같은 문제·n·최대 단계·최대 깊이 한도로 두 ExecutionRun을 생성합니다. 결과 카드는 각 실행의 최종 기록이며 현재 재생 위치와 구분합니다. 두 실행이 모두 정상 종료한 경우에만 결과 일치 여부를 표시합니다. 한쪽이라도 한도에 도달하면 부분 값을 최종 결과로 비교하지 않습니다.

**재귀 단계 보기 / 반복 단계 보기**는 단일 공통 재생기에 선택한 실행을 연결합니다. 각 실행의 관찰 인덱스를 따로 기억하고 복원하며 자동 실행은 멈춥니다. 입력 변경 시 두 기록과 관찰 위치 모두 초기화합니다. 같은 Step 번호가 같은 계산량이라는 의미는 아닙니다.

| 지표        | 정의                                                            |
| ----------- | --------------------------------------------------------------- |
| calls       | 직접 정의한 함수의 진입. 최초·기저 호출 포함                    |
| maxDepth    | 동시에 살아 있는 프레임 최대 수. 최초 깊이 1                    |
| comparisons | 실제 if/while 조건 평가. 마지막 거짓 검사 포함                  |
| assignments | 표시 코드의 = 완료. 매개 변수 바인딩·함수 정의·global 선언 제외 |
| arithmetic  | 실행된 +, −, × 각각 1회. 재귀 인수 계산과 반복 i 증가 포함      |
| iterations  | 반복 몸체 첫 대입의 실행 횟수. 마지막 거짓 조건은 제외          |

반복 방식도 함수 안에서 실행하므로 호출 1회·깊이 1을 사용합니다. 한 대입 사건에서 산술과 대입 지표가 함께 늘 수 있으며 지표를 합산하지 않습니다. 재생 속도·스냅샷 복제·렌더링 비용·실제 경과 시간은 집계하지 않습니다. 작은 입력의 측정값으로 Big-O를 자동 판정하지 않습니다.

## 호출 트리 탐색

중첩 목록과 연결선을 통해 실제 부모·자식 관계를 표시합니다. n=8 피보나치는 67개 호출을 기록합니다. 완료한 가지를 접거나 모두 펼치고 글자를 100–150%로 확대할 수 있습니다. 그림 영역의 가로·세로 스크롤과 키보드 접근을 지원합니다. 현재 실행 경로는 접히지 않으며 과거로 되돌아갔을 때에도 활성 프레임 경로가 나타납니다.

접힌 가지에 숨긴 호출 수를 표시합니다. 접기·글자 크기는 표현 상태만 바꾸고 실제 호출 수·프레임·Step을 변경하지 않습니다. 알고리즘에서 탐색 가지를 배제한 것으로 표시하지 않습니다. 현재 호출이 바뀌면 해당 노드가 보이도록 그림 내부를 스크롤합니다.

## 한도와 검증 기준

기존 재귀 합 기본 한도는 160단계, 새 예제는 500단계이며 최초 호출을 포함한 깊이 한도는 13입니다. UI에서 20·50단계 한도를 선택할 수 있습니다. 비교에서는 선택한 실행의 같은 한도를 두 방식에 전달합니다. 한도에는 초기·종료 기록이 포함되며, 한도 도달 Step은 마지막 안전한 상태를 보존합니다.

12!은 479,001,600으로 정확한 정수 범위 안에 있습니다. 피보나치 n≤8은 최대 67호출·370스냅샷으로 제한하여 호출 트리를 읽고 동기 실행을 끝낼 수 있게 합니다. 큰 입력은 지원하지 않으며 Worker/청크 실행은 이번 범위가 아닙니다.

검증은 알려진 합·팩토리얼·피보나치 결과, n=0/1, 두 재귀 호출의 순서와 지역 변수, 변수 범위·None, 매 사건의 지표와 코드 줄, 스냅샷 동결·왕복, 입력·단계·깊이 한도, 실제 브라우저의 패널 동기화·비교 위치 복원·가지 접기를 포함합니다.
