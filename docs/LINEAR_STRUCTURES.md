# 큐·스택 실습 계약

## 학습 범위

큐의 FIFO, 스택의 LIFO, 삽입·삭제 위치와 반환값을 관찰합니다. 직접 조작과 예제 실행은 같은 순수 모델을 사용합니다. 자동 채점이나 학생 활동 수집은 없습니다.

두 예제는 동일하게 1, 2, 3, 4를 넣고 네 번 삭제합니다. 큐의 삭제 순서는 1→2→3→4, 스택은 4→3→2→1입니다. 예제 교체 시 실행은 초기화되므로 두 예제를 각각 관찰하고 설명하는 활동입니다. 동시에 재생하는 비교 모드는 아닙니다.

## 구조와 포인터

- 모델의 `items`는 논리적 저장 순서입니다. 큐는 Front→Rear, 스택은 Bottom→Top입니다.
- 포인터는 0부터 시작합니다. 원소가 있으면 큐 Front=0, Rear=length−1, 스택 Top=length−1입니다. 빈 구조에서는 모두 `null`입니다.
- 큐는 뒤에 삽입하고 앞에서 삭제합니다. 스택은 마지막에 삽입하고 마지막에서 삭제합니다.
- 시각화는 스택의 Top을 위에 표시하지만 저장 배열 순서는 Bottom부터입니다.
- 화면 용량은 6개입니다. 빈칸 표시는 가독성을 위한 용량 안내이며 실제 배열 메모리 예약이 아닙니다. 순수 모델의 개발·테스트용 용량 인수는 1~8을 지원합니다.
- 큐 삭제 후 위치 번호가 줄어드는 것은 논리적 순서 재표시입니다. Python 표시는 `collections.deque`를 사용하며 메모리 이동량이나 리스트 `pop(0)`의 비용을 측정했다고 해석하지 않습니다.

## 직접 조작과 예제 실행

직접 조작은 명령을 추가할 때 최대 40개 명령을 처음부터 결정적으로 다시 추적하고 마지막 상태로 이동합니다. 이전 명령의 결과는 같은 입력으로 재생성되므로 동일하며 이전 상태는 동결됩니다. 기존 `Player`의 이전/다음/자동 실행은 이 기록을 재생합니다.

직접 조작 기록의 중간 단계에서는 새로운 명령을 넣을 수 없습니다. ‘마지막 단계로’ 이동한 뒤 추가합니다. 이는 이전에 기록한 미래 사건을 실수로 덮어쓰지 않게 하는 구현 선택입니다.

실습 방식·자료구조·학습 공간 변경 및 새 실습은 명령, 기록, 포인터와 누적 지표를 초기화하고 타이머를 정지합니다. 직접 조작 입력값은 실행 전체의 매개 변수와 달리 다음 삽입의 인수이므로 수정 시 기존 자료구조를 유지하고 자동 재생만 멈춥니다. 화면에 이 차이를 안내합니다.

## 표시 코드와 사건

큐는 `deque()`, 스택은 리스트를 사용한 Python 코드를 표시합니다. 구조 선언과 용량 상수는 초기 상태 전에 준비되며 초기 상태의 `source`는 `null`입니다. 그 아래 명령만 추적합니다. `removed`는 첫 성공한 삭제 전에는 아직 대입되지 않았습니다.

각 명령은 네 줄의 조건·성공 분기·else·안내 출력을 표시하고 다음 두 Step을 생성합니다.

1. `compare`: 삽입의 용량 검사 또는 삭제의 빈 구조 검사. 구조는 그대로입니다.
2. `insert`/`remove`/`reject`: 실제 분기를 실행한 뒤의 상태. 삭제와 `removed` 대입은 한 Step에 묶습니다. 거절 사건은 해당 Python `print` 줄에 대응하고 한국어 설명에 이유를 표시합니다.

내장 메서드는 자료구조의 한 연산으로 취급합니다. 메서드 내부 프레임과 실행 비용을 별도로 추적하지 않습니다. `remove` 사건의 `returnValue`에 실제 반환값이 있고, 함수 프레임 복귀가 아니므로 `returnInfo`는 `null`입니다. 다음 조건 검사/삽입/거절에서는 `returnValue`를 비우되 전역 `removed`는 마지막 성공한 값을 유지합니다.

## 거절과 한도

빈 구조의 삭제와 가득 찬 구조의 삽입은 `reject` 사건입니다. 조건의 실패를 정상적으로 처리했으므로 실행 상태는 `running`이고 구조·포인터·기존 removed를 변경하지 않습니다. 거절 다음에도 조작을 계속할 수 있습니다. 예제의 명령 목록을 모두 처리하면 `completed`입니다.

직접 조작은 다음 입력을 받을 수 있는 열린 기록이므로 마지막 사건의 상태가 `running`입니다. 재생기가 마지막 위치에서 멈추는 것과 예제의 정상 종료를 구분합니다.

값은 −99~99 정수이고 0·음수·중복을 허용합니다. 잘못된 형식은 실행 전에 안내하며 기존 기록을 유지합니다. 빈/가득 찬 구조의 요청도 40회 조작 한도에 포함합니다. 40회에서 조작 버튼을 막고 새 실습을 안내합니다. 공통 Step 한도는 100개이며 실제 40회 직접 조작은 81개, 정규 예제는 18개 스냅샷입니다. 더 낮은 개발용 Step 한도에 도달하면 `limit-reached`를 기록합니다.

## 지표

| 지표          | 정의                                  |
| ------------- | ------------------------------------- |
| `inserts`     | 성공한 삽입마다 1                     |
| `removes`     | 성공한 삭제마다 1                     |
| `rejected`    | 빈 구조·용량 초과로 거절한 요청마다 1 |
| `comparisons` | 각 명령의 if 조건 평가마다 1          |
| `assignments` | 성공한 삭제에서 removed에 대입할 때 1 |
| `maxSize`     | 현재까지 동시에 저장된 최대 원소 수   |

원소 이동·실제 실행 시간·메서드 내부의 호출 횟수나 산술량은 집계하지 않습니다. 기본 프레임 지표는 0이며 선형 자료구조 분석 화면에서는 적용 가능한 지표만 표시합니다. 지표는 서로 더하지 않습니다.
