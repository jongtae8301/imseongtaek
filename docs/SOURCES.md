## 첫 예제의 근거와 차이

교과서 PDF 24–26쪽(인쇄 33–35쪽)은 1부터 k까지의 합을 반복과 재귀 관계로 설명합니다. PDF 26쪽(인쇄 35쪽)의 종료 조건을 갖춘 코드는 `f(1)=1`, `f(k)=f(k-1)+k`를 사용합니다.

이번 `sum_to`는 **교과 개념을 바탕으로 새로 구성한 예제**입니다. 교과서 코드를 그대로 재현했다는 표시는 사용하지 않습니다.

| 차이                                                   | 이유와 영향                                                                                                      |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 기저값을 `sum_to(0)=0`으로 설정                        | 최소 입력과 실제 반환값 0을 관찰합니다. 양의 n에 대한 합은 같지만 호출 횟수·깊이는 교과서 예제보다 1 증가합니다. |
| `smaller`, `subtotal`, `total` 지역 변수로 계산을 분리 | 인수 계산·반환값 수신·최종 합의 대입 시점을 별도로 관찰합니다. 대입 집계는 원본 코드와 다릅니다.                 |
| `n = 입력값`, `result = sum_to(n)` 표시                | 브라우저에서 검증한 입력이 어떤 전역 변수에 전달되는지 관찰합니다. 콘솔 `input`/`print`는 제공하지 않습니다.     |
| 입력 범위 0~12                                         | 호출 구조의 가독성과 제한된 동기 계산량을 보장합니다.                                                            |

기저 조건의 차이는 의도적인 교육용 변형이며 교과서 오류 수정이 아닙니다. 범위 확장이나 원문 재현 예제를 추가할 때 기준 정의를 다시 명시해야 합니다.

## 큐·스택 확장에서 추가 확인한 자료

같은 교과서의 PDF 72·73·74쪽(인쇄 81·82·83쪽)과 PDF 86·87·88쪽(인쇄 95·96·97쪽)을 읽었습니다. 큐의 FIFO 정의와 은행 번호표 활동, 스택의 LIFO 정의와 객차 순서 활동 및 리스트 삽입 구현을 참고했습니다.

은행 예제는 네 명이 차례로 들어온 뒤 네 번 삭제하는 활동으로 새로 구성했습니다. 객차 예제는 1→2→3→4 진입 후 삭제하여 역순으로 나오는 개념을 사용하되, 실제 철도 선로 그림 대신 공통 스택 시각화를 사용합니다. 둘 다 교과 개념을 바탕으로 새로 구성한 예제로 표시합니다. 은행의 대기 포기 조건이나 객차의 모든 순열 가능성 판별은 이번 구현 범위가 아닙니다.

큐의 교과서 삽입/삭제 용어는 push/pop이지만, 화면에서는 큐 연산 구분을 위해 Enqueue/Dequeue와 한국어 삽입/삭제를 함께 사용합니다. 표시 Python 코드는 deque의 append/popleft를 사용하며, 스택은 리스트 append/pop을 사용합니다. 이는 API 표현 선택이며 FIFO/LIFO 규칙은 같습니다.

큐 화면은 Front를 왼쪽, Rear를 오른쪽에 두고 0부터 센 논리적 위치를 표시합니다. 교과서 은행 표의 입구/출구 배치와 그림 방향이 다르므로 화면과 실습 계약에 방향을 명시했습니다. 물리적 배열 또는 순환 큐 포인터를 재현한 것은 아닙니다.

용량 6개, 정수 −99부터 99, 직접 조작 40회 한도와 조건 검사·거절 사건 구분은 개발상 선택입니다. 교과서 원문에서 확정한 수치로 소개하지 않습니다.
