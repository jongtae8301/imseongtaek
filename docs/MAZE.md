# 미로 BFS·DFS 비교 활동

사용자가 ‘미로는 코드 없이 직접 수정하면서 두 탐색의 차이만 나란히 비교’하도록 요청하여, 미로를 비교 전용 화면으로 변경했습니다. 공통 여섯 패널 규칙에 대한 **미로 활동만의 사용자 지정 예외**입니다. 일반 그래프·트리의 코드와 행렬·리스트 화면은 기존대로 제공합니다. 이 미로는 교과의 그래프 탐색 개념을 적용한 새 변형 예제이며, 교과서 원문 미로 또는 8퍼즐을 재현한 것이 아닙니다.

## 화면과 사용 흐름

1. **그래프와 탐색 → 미로 BFS·DFS**를 엽니다. BFS·DFS 그림 두 개와 공통 편집 도구가 바로 보입니다. 첫 기록은 미리 준비하지만 자동으로 재생하지 않습니다.
2. 미로 예제를 고르거나 어느 쪽 미로든 직접 편집합니다. **클릭은 벽 켜기·끄기**, **드래그는 첫 칸이 길이면 생성, 벽이면 삭제**입니다. 중간에 이미 벽인 칸이나 빈 칸을 지나도 도구가 바뀌지 않습니다. 빠르게 끌어도 지나간 중간 칸을 채우며, 같은 칸을 다시 지나도 뒤집지 않습니다. **S(출발)·G(도착)는 끌어 놓아서 이동**합니다. 하나의 미로 모델을 공유하므로 같은 수정이 양쪽에 반영됩니다.
3. **같이 탐색**으로 두 탐색을 재생합니다. 기록이 없으면 먼저 Worker에서 준비한 뒤 시작합니다. **한 칸씩**도 필요한 기록을 준비한 뒤 한 번 전진합니다.
4. **일시 정지**, **이전**, **한 칸씩**, **처음으로**는 두 그림에 함께 적용합니다. **결과 비교**는 각각의 출구 발견 시점(발견하지 못한 경우 마지막 안전한 상태)으로 이동합니다. 끝에서 **다시 비교**를 누르면 같은 입력으로 처음부터 재생합니다.
5. 각 그림 아래의 **발견한 칸 수**, **출구까지 경로의 이동 횟수**를 비교합니다. 벽 하나를 바꾼 뒤 두 값이 어떻게 달라질지 예상하고 다시 실행해 봅니다. 이웃 순서는 접힌 **이웃 순서·활동 안내**에서 바꿉니다.

사용자의 직접 조작 요청에 따라 도구 선택을 없애고 클릭·드래그로 통합했습니다. 우클릭은 사용하지 않습니다. 출발·도착을 누르기만 하면 벽으로 바꾸지 않습니다. 벽 드래그도 끝점을 건너뜁니다. 끝점은 놓는 순간에만 이동하며, 지나온 벽은 유지하고 벽에 놓았을 때 도착한 칸만 엽니다. 미로 밖에 놓거나 Esc·포인터 취소가 발생하면 끝점 이동을 취소합니다. 겹친 끝점은 기본 끌기로 출발, Shift+끌기로 도착을 옮깁니다.

**편집 되돌리기 / 편집 다시하기**는 최근 50개 작업을 저장하며 한 번의 드래그 전체를 한 작업으로 묶습니다. 끝점 이동, 벽 전체 지우기, 예제 교체도 복원합니다. Ctrl+Z, Ctrl+Shift+Z 또는 Ctrl+Y를 지원하며 macOS에서는 Cmd도 가능합니다. 되돌린 뒤 새로 편집하면 다시하기 기록을 비웁니다. 벽 그리기를 중간 취소하면 이미 적용한 칸은 유지하고 한 번에 되돌릴 수 있습니다. 이웃 순서는 편집 이력에 포함하지 않습니다. 이력은 활동을 떠나거나 새로고침하면 사라집니다.

방향키로 칸을 이동하고 Enter·Space로 벽을 토글합니다. Delete·Backspace는 벽 삭제, S·G는 선택한 칸으로 끝점을 옮깁니다. 각 그림의 탭 진입점은 하나이며 내부 이동은 방향키로 합니다. 편집·되돌리기·예제·이웃 순서 변경은 두 실행과 준비 작업을 중지하고 관찰 기록을 초기화합니다. 실제 미로가 변하지 않은 동작은 이력을 추가하지 않습니다. 탐색 재생의 **이전**은 편집 되돌리기와 별개입니다.

768px 이상은 두 그림을 나란히, 더 좁은 화면은 읽고 수정할 수 있는 크기를 유지하여 위아래로 배치합니다. 별도의 편집용 세 번째 그림, 코드 탭, 상세 상태·자료구조·실행 기록·분석 패널과 하단 고정 재생 바는 사용하지 않습니다. 모든 내용은 페이지 세로 스크롤로 읽습니다.

## 모델과 실행 계약

- 격자는 세로 2–15칸, 가로 2–21칸, 점은 길, #은 벽입니다. 좌표는 1부터 세는 행,열이며 왼쪽 위는 1,1입니다. 출발·출구는 길 위에 있고 같은 칸일 수 있습니다.
- 길 하나를 정점 하나로, 벽 없는 상하좌우 연결을 무방향 간선으로 바꿉니다. 대각선 이동과 가중치는 없고 한 번 이동의 비용은 1입니다.
- 이웃 순서는 **위 → 오른쪽 → 아래 → 왼쪽** 또는 정확한 역순입니다. 두 탐색에 같은 순서를 적용합니다.
- maze-search는 기존 buildSearchRun과 TraceRecorder를 공유합니다. 원본 Step에는 코드·프레임·큐·부모·경로·누적 지표를 유지하며 화면에만 해당 세부 정보를 생략합니다. `recording: 'full'`은 모든 사건을 기록하고, 비교 화면의 Worker는 `'discoveries'`로 초기·새 발견과 부모가 준비된 시점·종료만 저장합니다. 두 모드는 같은 알고리즘과 집계를 사용하며 저장하지 않은 사건도 실행합니다. 기록 모드는 메타데이터에 명시합니다.
- 일반 그래프의 A–Z / 최대 8정점, 일반 조작 큐의 기존 용량·입력값 −99–99 제한은 변경하지 않습니다. 미로용 큐는 최대 315개와 해당 격자 정점의 0 기반 인덱스를 허용하며 같은 순수 FIFO 전이를 사용합니다.

## 비교 재생과 발견 시점

내부 실행기는 닿는 영역 전체의 Step을 생성합니다. **비교 화면의 각 탐색은 출구를 처음 발견한 시점까지만 재생하고 그 그림과 지표를 유지합니다.** 출구를 못 찾은 쪽은 정상 완료 또는 한도 중단까지 보여 줍니다. 먼저 끝난 쪽을 고정해 둔 채 다른 쪽의 관찰을 계속합니다.

exitMilestone은 출구가 **발견 기록에 있고 부모 경로도 생긴 첫 스냅샷**을 고릅니다. BFS의 발견 직후에는 부모 기록이 아직 없을 수 있고, DFS의 부모 대입 직후에는 발견 전일 수 있어 두 조건을 함께 검사합니다.

player/maze-comparison.ts의 buildMazeComparison은 원본 Step에서 **새 칸을 발견하고 그 부모도 기록된 시점**을 하나씩 고릅니다. 초기 상태와 도달 불가·한도 중단의 마지막 상태도 보존합니다. 한 박자에 각 알고리즘의 다음 발견 장면을 보여 주며 서로 다른 원본 Step 번호를 그대로 유지합니다. 같은 박자가 같은 연산량이나 실제 계산 시간을 뜻하지 않습니다. 렌더러는 탐색 순서와 경로를 계산하지 않습니다.

공통 createPlayer의 단일 타이머가 두 스냅샷의 쌍을 재생합니다. 이전→다음으로 그림·경로·지표를 함께 복원하고, 끝에 도달하면 타이머를 제거합니다. 초기화·속도 변경·재생 중 수동 이동에도 공통 재생 규칙을 적용합니다.

- 발견한 칸: 현재 표시한 스냅샷까지 visited에 처음 넣은 칸 수입니다. 시작 칸도 포함합니다.
- 출구 경로: 부모 경로의 간선 수(이동 횟수)입니다. 출발=출구이면 0회입니다.
- ●와 진한 테두리: 이번 관찰에서 새로 발견한 칸입니다. 원본 코드의 처리 중 정점과 구분합니다.
- 발견한 칸은 +와 옅은 면, 출구 경로는 녹색과 이동 순서 숫자, 끝점은 S/G로 표시합니다.
- BFS는 동일 비용의 이동에서 최단 경로를 찾습니다. DFS의 발견 경로는 최단을 보장하지 않습니다.
- 출구 미발견 상태의 정상 완료는 ‘도달 불가’, 한도 중단은 ‘미확정’입니다. 실제 시간이나 전체 탐색량을 겨루는 순위·승패를 표시하지 않습니다.

기본 9×13 갈림길 미로의 기본 이웃 순서에서 BFS는 59칸 발견·12회 이동, DFS는 21칸 발견·20회 이동입니다. 기존 5×7 갈림길 예제는 BFS 18칸·6회 이동, DFS 11칸·10회 이동입니다. ‘더 적게 살펴봄’과 ‘더 짧은 길’이 다를 수 있음을 비교합니다.

## 한도·중단·확장

최대 315칸, 호출 깊이는 격자 면적까지 허용합니다. 알고리즘당 저장 단계 2,000개, 발견 장면 모드에서는 저장 여부와 별개로 실행 사건 50,000회를 제한합니다. 최대 빈 격자는 594개 무방향 간선·1,188회 이웃 확인이며, 초기·315개 발견·종료의 317개 스냅샷으로 끝납니다. 전체 기록 모드는 큰 격자에서 2,000단계 한도에 도달할 수 있으며 정상 완료로 표시하지 않습니다. 학생용 단계 한도 선택은 제공하지 않습니다.

maze.worker.ts가 두 실행을 생성하고 비교에 필요한 시점들을 고른 후 메시지로 독립 복제하여 전달합니다. 출구 발견 이후의 불필요한 기록은 UI로 전송하지 않습니다. 큰 미로 준비에는 몇 초가 걸릴 수 있으나 UI 스레드는 계속 응답합니다. **준비 중단**, 입력 변경, 활동 변경·컴포넌트 해제는 Worker를 종료하고 이전 결과를 무시합니다. 준비 완료 후에는 공통 재생기의 타이머만 사용하며 화면은 스냅샷을 읽기 전용으로 사용합니다.

새 예제는 mazeSamples에 제목·rows·start·target을 등록하고 격자 검증, 독립적인 경로 기대값과 도달 불가 여부를 테스트합니다. 현재 UI는 5×7·7×7·9×13·15×21 예제의 칸을 수정하며 임의 크기 입력과 파일 저장은 제공하지 않습니다. 작은 화면에서 큰 격자의 칸은 작아지므로 정밀 편집에는 작은 예제 또는 키보드를 사용합니다. 학생 입력과 편집 이력은 브라우저 메모리에만 있고 외부로 전송하지 않습니다.
