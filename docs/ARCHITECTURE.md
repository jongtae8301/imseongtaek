# 구조와 확장 방법

## 데이터 흐름

```text
예제 선택 / 입력 검증
        ↓
예제 실행기 → TraceRecorder → ExecutionRun (메타데이터 + 불변 Step 열)
                                     ↓
                         Player (인덱스 + 단일 타이머)
                                     ↓
              App → 여섯 공통 패널에 같은 Step 전달
```

실행기의 내부 계산 상태만 가변이며, 매 사건에서 `structuredClone`으로 스냅샷을 만든 뒤 중첩 값까지 `Object.freeze`합니다. 렌더러는 알고리즘이나 결과를 계산하지 않습니다. 호출 트리와 콜 스택도 실행기가 생성한 데이터로 표시합니다.

## 책임과 경계

| 계층         | 책임                                          | 금지할 결합                         |
| ------------ | --------------------------------------------- | ----------------------------------- |
| `engine`     | 공통 계약·기록·직렬화 가능 값·종료 구분       | React, DOM, 애니메이션 타이머       |
| `examples`   | 검증된 입력·표시 코드·학습 목표·알고리즘 사건 | 화면 요소 직접 변경, 임의 코드 평가 |
| `player`     | 저장된 Step의 인덱스·속도·중지·경계           | 알고리즘 재계산, 상태 역연산        |
| `components` | 읽기 전용 스냅샷의 표시                       | 방문 순서·반환 결과 독자 계산       |
| `App`        | 예제와 재생기 연결·입력 초기화                | 알고리즘 정답 계산                  |

`createPlayer`는 React 없이 테스트 가능한 구독 저장소입니다. 예약된 `setTimeout`은 최대 하나입니다. 수동 탐색·입력 변경·dispose는 예약을 해제합니다. 속도 변경은 현재 위치를 유지한 채 새로운 간격으로 한 번만 예약합니다.

## 새 예제 추가

1. 관련 교과서 쪽과 학습 목표를 확인하고 원본 예제/변형 예제를 구분합니다.
2. `src/examples/`에 예제 ID, 표시 코드, 줄 번호 매핑, 입력 검증, 알고리즘 버전, 한도, 집계 정의와 학습 활동을 작성합니다.
3. 입력을 검증한 뒤 초기 상태를 기록합니다. 사건을 실행하고 `TraceRecorder.emit`으로 사건 **실행 후**의 상태를 생성합니다.
4. 호출·복귀나 자료구조 조작 시 ID·변화 내용·반환 대상과 한도 상태를 기록합니다.
5. 작은 입력을 수작업으로 추적한 기대값으로 최종 결과와 중간 상태 테스트를 추가합니다.
6. 공통 계약으로 설명할 수 없는 데이터가 있으면 `engine/types.ts`를 갱신하고 관련 실행기·재생기·렌더러·테스트도 함께 변경합니다.
7. 해당 구조를 표시할 컴포넌트를 연결합니다. `Structure`의 예약된 구조 형식은 렌더러가 구현되어 있다는 뜻이 아닙니다.
8. 실제로 동작하는 예제만 `registry.ts`에 등록하고 선택 UI를 연결합니다. 예제 변경 시 기존 입력·기록 처리 정책을 정의하고 `player.load`로 인덱스와 타이머를 초기화합니다.
9. 관련 단위 테스트, 브라우저 테스트와 빌드를 통과시킨 뒤 README와 개발 계획을 갱신합니다.

현재 등록부는 일반 함수, 합·팩토리얼·피보나치의 재귀/반복, 은행 대기열, 객차 순서와 그래프·트리의 BFS/DFS 기본 예제를 연결합니다. 그래프 작업 공간은 직접 편집한 입력도 같은 실행기에 전달합니다. 임의 문자열 ID의 예제 로딩이나 자유 코드 편집 API는 아직 없습니다.

## 큐·스택 확장

`structures/linear.ts`의 `applyLinearCommand`가 삽입·삭제·요청 거절의 유일한 기준입니다. 상태를 변경하지 않고 새 상태와 전이를 반환합니다. `linearStructure`가 포인터를 계산합니다. 실행기와 UI는 각자 삭제 순서를 계산하지 않습니다.

`examples/linear.ts`는 명령 목록을 받아 조건 검사와 성공/거절 사건을 만들고 같은 `TraceRecorder`로 기록합니다. 직접 조작은 40개 이하의 명령 목록을 결정적으로 다시 추적하고 마지막 스냅샷으로 이동합니다. 예제 모드는 같은 모델의 스냅샷을 재생합니다.

`App`은 학습 공간 전환을 담당하며 `workspaces/RecursionWorkspace`와 `workspaces/LinearWorkspace`가 입력과 재생기를 소유합니다. 공간을 전환하면 이전 재생기를 해제합니다. 코드·실행 기록·분석·학습 안내·재생 버튼과 키보드 처리는 두 공간에서 공유합니다. 직접 조작의 지난 기록은 읽기 전용이며 미래 기록을 묵시적으로 덮어쓰지 않습니다.

## 함수 예제와 비교 확장

`FunctionTrace`는 표시 코드의 이름별 줄 매핑을 받아 함수 진입·복귀, 프레임별 변수, 전역 변수와 누적 지표를 기록합니다. 제한된 실행기에서 직접 호출하며 Python 문자열을 평가하지 않습니다. 기존 재귀 합은 그대로 사용하고, `examples/functions.ts`가 일반 함수·팩토리얼·피보나치·반복 예제와 공통 입력 검증·비교 실행을 제공합니다.

`examples/lesson.ts`는 표시 계층에 의존하지 않는 학습 안내 계약입니다. 새 예제는 functionExamples의 정의·한도·활동과 registry의 실행 등록을 함께 갱신합니다. 재귀/반복 비교는 입력·한도를 공유한 두 Run을 유지하고 선택한 한 Run만 공통 재생기에 연결합니다. 전환 전후 인덱스를 따로 보관하며 입력 변경 시 둘 다 초기화합니다.

`CallTreePanel`은 Step의 parentId로 중첩 목록을 배치합니다. 접은 가지와 글자 크기는 화면 전용 상태이며 방문이나 연산량을 계산하지 않습니다. 활성 호출 경로는 항상 펼칩니다. `StackPanel`은 같은 Step의 호출 노드에서 호출 당시 인수 표기를 가져오고, 현재 매개 변수는 이름=값으로 별도 표시합니다.

## 그래프·트리 확장

`structures/graph.ts`는 방향·정점 순서·간선을 하나의 모델로 관리하고 행렬/리스트 입력을 엄격하게 검증합니다. 트리 관계와 이진 배열 위치도 여기에서 생성합니다. `GraphEditor`는 검증한 모델을 작업 공간에 전달하는 입력 컴포넌트입니다.

`examples/graph-search.ts`는 BFS/DFS의 방문·처리 순서, 프런티어, 부모·경로, 프레임과 지표를 계산합니다. BFS는 기존 순수 큐 모델을 재사용하며 DFS는 공통 Frame/returnInfo 계약을 사용합니다. 그래프의 연결, 검증한 트리 관계와 탐색 상태를 Step에 담습니다.

`GraphWorkspace`가 입력·단일 재생기를 소유하며 그래프/트리 메뉴 전환 시 해제합니다. 비교는 같은 입력의 두 ExecutionRun과 독립된 관찰 인덱스를 보존합니다. 최종 결과 카드는 각 실행의 마지막 Step, 과정 전환은 선택한 실행의 현재 Step을 사용합니다. 편집 미리보기는 GraphCanvas에 그래프 모델만 전달하며 실행 상태를 생성하지 않습니다. 그래프 입력·사건·집계와 제한은 [탐색 계약](GRAPH_TRAVERSAL.md)에 기록했습니다.

`TreeWorkspace`는 `GraphWorkspace isTree`를 바로 표시합니다. 사용자 요청에 따라 거리·공통 조상 활동 선택과 실행 예제 등록을 제거했습니다. 이전 거리 구현 소스와 단위 검증은 참고용으로 보관하지만 앱에서 불러오지 않습니다. [이전 트리 거리 계약](TREE_DISTANCE.md)은 현재 제공 기능이 아닌 구현 기록입니다.

## 스타일과 접근성

`GraphActivities`는 기존 그래프 편집·탐색과 `MazeWorkspace`의 미로 비교를 전환합니다. `structures/maze.ts`가 검증된 격자를 그래프로 변환하고, `examples/maze-search.ts`가 같은 BFS/DFS 실행기를 호출합니다. `maze.worker.ts`는 두 실행의 준비를 UI 스레드에서 분리하며 입력 변경·중단·해제 때 종료됩니다. `exitMilestone`은 기존 Step에서 출구의 발견·부모 경로가 모두 존재하는 첫 기록을 선택합니다. `MazeBoard`는 편집 입력 또는 불변 실행 상태를 받아 표시하고 탐색을 계산하지 않습니다. [미로 계약](MAZE.md)을 참고하세요.

사용자 요청으로 미로는 두 편집 가능한 그림을 항상 보여 주는 비교 전용 화면입니다. `player/maze-comparison.ts`가 각 원본 Run에서 새 발견·부모 기록이 함께 존재하는 스냅샷을 선택하여 쌍으로 묶습니다. 먼저 출구를 찾거나 종료한 쪽의 마지막 프레임은 고정합니다. `createPlayer`는 steps를 갖는 타임라인을 제네릭으로 받아 기존의 단일 타이머·경계·정지·복원 로직을 그대로 재사용합니다. 원본 Step의 번호·지표를 재작성하거나 다른 탐색을 실행하지 않습니다. 미로는 여섯 패널 대신 두 그림·발견한 칸 수·경로 길이를 같은 쌍의 스냅샷에서 표시합니다.

`GraphCanvas`의 드래그 좌표는 `GraphEditor` 안의 표시 상태입니다. 정점·간선 수정은 기존 `createGraph`/`setEdge`를 사용하며 미적용 문자 입력과 동시에 수정하지 않습니다. 트리 미리보기는 `treeInfo`가 검증한 관계만 계층으로 배치하고 잘못된 연결을 묵시적으로 고치지 않습니다.

로컬 CSS와 시스템 글꼴을 사용합니다. `styles.css`는 기존 구조 컴포넌트의 스타일을, 뒤에 불러오는 `workbench.css`는 [DESIGN.md](../DESIGN.md)의 화면 배치·정보 위계·반응형 규칙을 담당합니다. 기본은 큰 시각화와 선택한 정보 패널의 두 열이며 좁은 화면에서는 탭 하나만 표시합니다. 재생 제어는 화면 하단에 고정적으로 접근할 수 있습니다. 내용 높이는 제한하지 않고 페이지 세로 스크롤을 사용합니다. 화면 전체 확대와 자료구조의 가로 스크롤을 허용하고, 현재 호출/대기/복귀 완료에 색상과 텍스트를 함께 사용합니다.

`ObservationPreferencesProvider`는 설정 접힘(기본 true)·전체 영역 표시(기본 false) 선호를 앱 메모리에 유지합니다. `ObservationPanels`와 `useObservationView`는 선택한 탭·반응형 표시·포커스 이동을 담당합니다. 900px를 초과하면 시각화와 다섯 정보 탭을, 900px 이하면 시각화를 포함한 여섯 탭을 제공합니다. 전체 펼치기에서도 동일 컴포넌트를 유지합니다. 숨긴 패널도 같은 Step을 전달받고 호출 트리의 활성 호출에 대한 가로 스크롤만 보정합니다. 화면 상태는 Player의 기록·인덱스·지표를 바꾸지 않습니다. [관찰 화면 계약](OBSERVATION.md)을 참고하세요.

`HistoryPanel`은 현재 단계까지 최근 8개 또는 전체 기록을 표시하며 기록 자체를 변경하지 않습니다. 전체 펼침은 해당 실행 객체에 연결되어 새 입력에서는 접힌 상태로 돌아갑니다. `PlaybackControls`의 `ResizeObserver`는 바의 실제 높이를 `--playback-height`에 반영하고, CSS는 페이지 하단 여백과 루트 스크롤 여백에 이를 사용합니다. 코드·기록의 자동 세로 스크롤과 패널 내부 높이 제한은 제거했습니다.

코드 강조는 `aria-current="step"`, 상태 설명은 `role="status"`, 오류는 `role="alert"`로 제공합니다. 자동 실행은 사용자가 시작하며 초기 화면에서 자동으로 진행하지 않습니다. 입력값이나 학습 활동은 저장하지 않습니다.
