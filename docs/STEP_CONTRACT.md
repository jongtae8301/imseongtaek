# 공통 Step 계약

트리 거리 활동은 [트리 거리 계약](TREE_DISTANCE.md)의 `tree-distance` 구조를 추가합니다. 입력 from/to, 현재 a/b, trailA/trailB, 현재 이동 간선, 누적 distance, lca와 path를 불변 스냅샷에 담습니다. 미대입 포인터·거리·LCA는 null이며 globals에서는 unset으로 대응합니다. search는 null이고 BFS/DFS의 방문 상태를 만들지 않습니다. 기존 assign/compare/complete/limit 사건과 집계를 재사용합니다. 부모 이동과 거리 증가를 별도 Step으로 기록합니다.

이 문서는 AGENTS.md의 개발 규칙을 코드로 구체화한 계약입니다. 기획안 원문 인용이 아닙니다. 기준 구현은 `src/engine/types.ts`와 `src/engine/trace.ts`입니다.

## 시간과 사건

- Step은 **사건 실행 후** 상태입니다. `index`는 초기 상태 0부터 연속 증가합니다.
- `source`는 해당 사건이 진행된 Python 코드 줄입니다. 초기·종료·한도 사건은 `null`입니다.
- 한 줄의 함수 호출과 대입은 여러 사건으로 분리됩니다. `subtotal = sum_to(smaller)`의 호출 사건은 새 프레임 생성 후 상태이며 아직 subtotal이 대입되지 않았습니다. 복귀 다음의 대입 사건에서 같은 줄이 다시 강조됩니다.
- `n - 1`과 `n + subtotal`의 계산 및 대입은 각각 한 Step에 묶입니다. 해당 Step에서 산술과 대입 지표가 각각 1 증가합니다. 단계 수는 계산량이 아닙니다.
- 함수 정의는 준비된 상태에서 시작하며 함수 정의 사건과 정의 비용은 추적하지 않습니다. 실제 변수 대입과 호출은 코드 9~10번 줄부터 추적합니다.

## 실행 메타데이터

`ExecutionRun.metadata`는 예제 ID, 입력값, 알고리즘 버전, 코드 ID·언어·줄 목록, 이름별 줄 매핑, 이웃 방문 순서, 지표별 집계 규칙, 실행 한도, `after-event` 의미를 보관합니다. 재귀 합에는 이웃 방문 순서가 적용되지 않아 `null`입니다.

## 스냅샷 필드

| 필드                        | 의미                                                            |
| --------------------------- | --------------------------------------------------------------- |
| `index`, `event`, `status`  | 단계 번호, 사건 종류, 실행/정상 종료/오류/한도 도달/중단        |
| `source`                    | 방금 진행한 코드 위치 또는 코드와 무관한 사건의 `null`          |
| `activeFrameId`, `frames`   | 현재 실행 대상과 살아 있는 호출 프레임. 배열은 바닥→Top 순서    |
| `globals`                   | 전역 값. 같은 이름의 매개 변수와 별개                           |
| `returnValue`, `returnInfo` | 이번 반환 사건의 값, 제거된 프레임 ID, 복귀 프레임과 코드 위치  |
| `structures`                | 호출 트리·순차 구조·그래프·테이블의 구별 가능한 구조 데이터     |
| `search`                    | 현재 대상·발견·처리 완료·대기열·경로·배제 근거. 미적용은 `null` |
| `metrics`                   | 현재까지 누적 호출·비교·대입·산술과 최대 동시 프레임 수         |
| `explanation`, `changes`    | 한국어 사건 설명 및 이전 값→새 값과 변경 위치                   |

각 프레임은 고유 ID, 함수명, 부모 ID, 매개 변수, 지역 변수, 호출 위치와 복귀 위치를 가집니다. 복귀 사건에서 반환한 프레임은 `frames`에서 이미 제거되며 부모가 활성화됩니다. `returnInfo`와 호출 트리가 복귀 기록을 보존합니다. 전역에서 호출한 프레임의 부모 ID는 `null`입니다.

호출 트리는 모든 생성된 호출을 유지합니다. 상태는 `active`/`waiting`/`returned`이며 각 노드에 깊이와 실제 반환값을 기록합니다. 호출이 끝났다는 이유로 트리 노드를 삭제하지 않습니다.

## 값의 존재 여부

```ts
{ kind: 'unset' }             // 아직 대입되지 않음, 화면: 아직 없음
{ kind: 'none' }              // 반환값 없음, 화면: None · 반환값 없음
{ kind: 'value', value: 0 }   // 실제 숫자 0
{ kind: 'value', value: '' }  // 실제 빈 문자열, 화면: ""
{ kind: 'value', value: [] }  // 실제 빈 구조, 화면: []
```

미대입 변수 이름을 관찰 목적으로 목록에 미리 보여주되 `unset`으로 구분합니다. 재귀 예제에서 현재 사건이 반환 사건이 아니면 `returnInfo`는 `null`이고 UI는 ‘반환 사건 아님’을 표시합니다. 반환 후 별도의 대입으로 값을 저장하며, 종료 결과는 `globals.result`에 남습니다. 큐·스택의 `remove` 사건은 내장 메서드의 삭제 반환값과 대입을 한 Step에 기록합니다. 이때 `returnValue`는 실제 반환값이고 `returnInfo`는 프레임 복귀가 아니므로 `null`입니다.

## 집계 규칙

| 지표      | 재귀 합 예제의 정의                            | 정상 종료 값 |
| --------- | ---------------------------------------------- | ------------ |
| 호출      | 최초·기저 호출을 포함해 `sum_to`에 진입        | n+1          |
| 비교      | `n == 0` 평가                                  | n+1          |
| 대입      | 코드의 `=` 완료. 매개 변수 전달·함수 정의 제외 | 3n+2         |
| 산술      | `n - 1`과 `n + subtotal` 각각 1회              | 2n           |
| 최대 깊이 | 동시에 살아 있는 `sum_to` 프레임 수의 최댓값   | n+1          |

기저 n=0은 7개 Step이며 일반 n의 전체 스냅샷 수는 6n+7입니다. 이 식은 현재 예제의 사건 분리 규칙에서 나온 값입니다. 지표는 합산하지 않습니다. 애니메이션 프레임·타이머·실제 경과 시간은 연산량에 포함하지 않으며 Big-O를 측정값에서 자동 추론하지 않습니다.

## 불변성·한도·오류

스냅샷은 JSON으로 직렬화할 수 있고 깊은 복제 및 동결됩니다. 이전 단계 복원은 저장된 스냅샷 선택으로 수행합니다. 같은 입력·버전·한도는 같은 실행을 만듭니다.

기본 한도는 n=0~12, 160단계, 동시 프레임 13개입니다. 테스트·개발에서는 더 낮은 단계/깊이 한도를 전달할 수 있습니다. 한도에 도달하면 마지막으로 기록된 상태를 보존하고 추가 `limit` 사건을 기록합니다. 종료 기록 공간은 단계 한도에 포함되며 `limit-reached`를 정상 완료와 구분합니다.

재귀 입력 오류는 실행 전 폼에서 안내하고 기존 실행을 비웁니다. 현재 순수 실행기는 검증된 입력만 받으며 잘못된 직접 호출에는 `RangeError`를 던집니다. `error`/`cancelled`는 향후 계산 중 오류·취소를 표현할 공통 계약입니다. 현재 ‘일시 정지’는 재생 정지이며 실행 데이터를 `cancelled`로 바꾸지 않습니다.

## 선형 자료구조 확장

`SequenceStructure`는 `capacity`, 삭제 순서인 `removedValues`, 이번 사건의 `transition`을 포함합니다. 전이는 요청 종류, 성공/거절, 대상 값, 연산 전 원소 목록, 삽입·삭제 위치와 거절 이유를 표현합니다. 연산 후 원소와 포인터는 같은 Step의 구조 상태입니다.

`reject`는 조건에 따라 수행하지 않은 요청이며 `running` 상태를 유지합니다. `inserts`, `removes`, `rejected`, `maxSize`는 선택적 지표입니다. 재귀 예제에는 미적용이므로 생략하고 선형 자료구조에서는 0부터 누적합니다. 메타데이터의 지표 규칙도 해당 선택적 필드에 맞춰 제공합니다.

선형 자료구조의 잘못된 입력은 다음 명령을 실행하기 전에 안내하며 기존 구조와 기록을 유지합니다. 구조/모드 교체는 전체를 초기화합니다. 큐·스택의 입력 한도, 준비 코드와 내장 메서드의 사건 단위는 [별도 계약](LINEAR_STRUCTURES.md)에 정의합니다.

## 그래프·트리 탐색 확장

`graph`는 방향·정점 순서·간선을, `tree.info`는 검증된 루트·관계·깊이·이진 배열을 보관합니다. `SequenceStructure.removedValues`는 JSON 값 목록이며, 선형 실습에서는 정수이고 BFS에서는 정점 이름입니다.

`discover`는 visited 추가, `edge`는 다음 이웃 획득, `visit`는 order 기록, `process`는 해당 정점의 이웃 처리 완료 사건입니다. DFS의 call/return은 프레임 생성·제거 후를 뜻합니다. BFS remove는 popleft 반환값을 returnValue와 전역 u에 남기며 returnInfo는 null입니다.

탐색 Step의 search는 알고리즘·시작·목표, 현재 정점·간선, 발견·방문·처리 순서, 큐/호출 경로, 탐색 부모·발견 경로 길이, 현재·목표 경로와 중복 건너뛴 이유를 보관합니다. outcome은 완료 전에 pending이고, 정상 종료 시에만 found/unreachable/traversed로 확정합니다. 한도에서는 pending을 유지합니다.

지표 discoveries/visits/edgeScans/skipped/finished를 추가했습니다. BFS maxSize는 대기 큐, DFS maxSize는 살아 있는 프레임의 최대 수입니다. 기존 재귀·선형 예제에는 해당 탐색 지표를 생략합니다. 준비 코드, 방문 시점, 누적 규칙과 한도는 [그래프·트리 탐색 계약](GRAPH_TRAVERSAL.md)을 따릅니다.

## 일반 함수·반복 확장

FunctionTrace는 공통 Frame/CallNode/returnInfo/changes 계약으로 새 함수 예제를 기록합니다. 매개 변수 대입은 frames.ID.parameters.이름, 지역 대입은 frames.ID.locals.이름, 전역 대입은 globals.이름 경로를 사용합니다. 호출 트리 label은 호출 당시 인수를 보존하고 프레임 값은 현재 값입니다.

scope 사건은 global 선언으로 참조하는 변수 범위를 설명합니다. 대입·호출·산술 비용을 증가시키지 않습니다. 실제 None을 반환해 호출자의 변수에 대입하면 그 변수에 kind: none을 저장하며, 아직 대입하지 않은 kind: unset과 구분합니다.

선택적 지표 iterations는 반복 몸체의 첫 대입을 실행할 때 1 증가합니다. 마지막 거짓 조건은 comparisons만 증가합니다. 재귀·반복 비교는 같은 입력과 단계·깊이 한도를 가진 독립된 Run이며 인덱스도 각각 보관합니다. 예제별 정의·한도·집계는 [함수 실습 계약](FUNCTIONS.md)에 기록했습니다.
