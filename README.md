# InfoScope

정보과학의 함수·자료구조·알고리즘을 단계별로 관찰하는 웹 실습 도구입니다.

**현재는 일반 함수·재귀·반복 비교, 큐·스택, 그래프·트리 그림 편집과 BFS/DFS, 미로 탐색 비교를 제공합니다.** 추가 재귀 예제와 8퍼즐·표현식 통합 활동은 후속 범위입니다.

## 현재 가능한 것

- 1부터 n까지 합을 구하는 재귀 예제, 입력 범위 0~12
- 일반 함수의 지역·전역 변수 변경과 None 반환, 팩토리얼·피보나치 예제
- 합·팩토리얼·피보나치의 같은 입력 재귀/반복 비교와 각 방식의 관찰 위치 복원
- 실제 부모·자식 관계의 다중 호출 트리, 완료 가지 접기·펼치기와 글자 확대
- 코드/문제, 시각화, 현재 상태, 자료구조, 실행 기록, 분석의 여섯 영역
- 프레임별 매개 변수·지역 변수와 전역 변수, 반환값과 복귀 위치
- 살아 있는 프레임만 표시하는 콜 스택과 복귀 기록도 보존하는 호출 트리
- 이전·다음·자동 실행·일시 정지·처음으로·속도 조절·단계 탐색
- 불변 스냅샷을 통한 정확한 되돌리기와 누적 연산량 복원
- 예상 → 관찰 → 자기 말로 설명 → 비교·재적용 안내
- 입력 변경 시 실행 중지와 이전 기록 초기화, 모바일 배치와 키보드 조작
- 큐·스택 직접 삽입·삭제, FIFO/LIFO, Front/Rear/Top과 삭제 반환 순서
- 같은 구조 모델을 쓰는 은행 대기열·객차 순서 예제 실행
- 연산 전후 구조 비교, 용량 초과·빈 구조 요청 거절과 기록
- 실제 구현된 학습 공간 사이 전환과 독립적인 실행 초기화
- 방향·무방향 그래프의 정점·간선 편집과 인접행렬·인접리스트 왕복
- 그림에서 정점 추가·삭제·드래그 배치, 두 정점 연결·해제와 행렬·리스트 자동 반영
- 벽·출발·출구를 편집하는 미로 BFS/DFS, 출구 발견 시점의 경로·탐색량 비교
- 트리 검증, 루트·부모·자식·형제·단말·깊이와 1기반 이진 트리 배열
- BFS 큐와 DFS 재귀 프레임, 발견·방문·처리 완료, 이웃 순서와 목표 경로
- 동일 입력의 BFS·DFS 결과·탐색량 비교, 미도달과 한도 도달 구분
- BFS·DFS 단계별 과정 전환과 각 탐색의 관찰 위치 복원
- 간결한 기본 화면: 큰 시각화와 정보 탭, 필요할 때 여는 예제·설정과 전체 영역
- 실행 방식별 학습 안내, 호출 당시 인수와 현재 매개 변수 구분, 그래프 편집 미리보기

현재는 검증된 예제와 직접 편집한 작은 그래프를 추적합니다. Python 소스는 읽기 전용이며 임의 코드를 실행하지 않습니다.

## 기술 구성

React 19.3.0, TypeScript 7.0.2, Vite 8.3.0, pnpm 11.19.0을 사용합니다. 버전은 실제 설치 결과이며 `package.json`과 `pnpm-lock.yaml`에 고정합니다.

- **React:** 같은 Step을 여섯 화면에 전달하고 컴포넌트별 표시 책임을 분리합니다.
- **TypeScript:** Step·프레임·구조·종료 상태 계약을 확인합니다.
- **Vite:** 로컬 개발 서버와 정적 파일 빌드를 제공합니다. [공식 시작 문서](https://vite.dev/guide/)를 확인했습니다.
- **Vitest / Playwright:** 독립적인 수작업 추적 결과와 재생기 타이머, 실제 브라우저 화면의 연결을 검증합니다.

서버, 데이터베이스, 계정, AI API, 외부 폰트/CDN, 사용자 추적을 추가하지 않았습니다. 실행 데이터는 브라우저 메모리에만 존재하며 새로고침하면 사라집니다. 개발 서버의 HMR 통신은 학생 데이터 저장 기능이 아닙니다.

## 시작하기

Node.js 22.12 이상과 pnpm 11.19.0이 필요합니다. 이번 환경에서는 기존 Node.js 24.19.0과 pnpm 11.19.0으로 설치·검증했습니다. Node가 설치된 다른 개발 PC에서 pnpm이 없다면 `npm install -g pnpm@11.19.0`으로 설치할 수 있습니다.

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

브라우저에서 개발 서버가 출력한 주소(기본 `http://127.0.0.1:5173`)를 엽니다. PowerShell 실행 정책이 `.ps1` 실행을 막는 환경에서는 `pnpm.cmd`를 사용할 수 있습니다.

```powershell
pnpm typecheck  # TypeScript 검사
pnpm test       # 실행기·재생기 단위 테스트
pnpm build      # 타입 검사 후 dist/ 정적 빌드
pnpm preview    # 빌드 결과 로컬 미리보기
pnpm test:e2e   # Edge 데스크톱/모바일 크기 브라우저 검사
pnpm format     # 원본 AGENTS.md를 제외한 프로젝트 코드 정리
pnpm check      # 서식·단위 테스트·타입 검사·빌드
```

`test:e2e`는 로컬 Microsoft Edge를 사용하며 전용 포트 4174에 Vite 서버를 자동 실행합니다. 테스트 프로세스 안에서 서버를 열고 닫아 Windows의 자식 서버 잔류를 방지합니다. Edge가 없는 개발 PC에서는 `pnpm exec playwright install msedge`로 설치하거나 `playwright.config.ts`의 채널을 사용 가능한 브라우저로 바꿉니다. 모바일 검증은 Edge의 작은 뷰포트 검증이며 실제 iOS 기기 검증은 아닙니다.

`dist/`를 HTTP 정적 호스팅으로 제공할 수 있도록 상대 경로 기반으로 빌드합니다. `file://`로 직접 여는 실행은 지원하지 않습니다.

## GitHub Pages 배포

`.github/workflows/deploy.yml`은 `main` 또는 `master`에 변경을 올리면 Node.js 24와 고정된 pnpm으로 설치하고 `pnpm check`를 통과한 `dist/`만 GitHub Pages에 배포합니다. 저장소의 **Settings → Pages → Source**는 **GitHub Actions**로 설정합니다. Actions 화면에서 수동 실행도 가능합니다.

- 소스의 `index.html`은 Vite의 진입 파일이고, 실제 배포 진입 파일은 빌드된 `dist/index.html`입니다.
- `base: './'`로 빌드하므로 저장소 하위 주소에서도 JavaScript·CSS·미로 Worker를 같은 위치 기준으로 불러옵니다.
- `node_modules`, 테스트 결과, 임시 파일, 환경 파일, 교과서 PDF와 기획안 원본은 업로드 대상에서 제외합니다.
- 호스팅을 위해 학생 계정·데이터베이스·API 키를 추가할 필요가 없습니다.

배포 구성은 [Vite의 GitHub Pages 안내](https://vite.dev/guide/static-deploy.html#github-pages)를 기준으로 작성했습니다.

## 조작과 한도

사용자 요청에 따라 실행 한도 설정칸을 제거했습니다. 각 실행기의 기본 안전 한도는 내부에서 적용하며 한도 도달 상태도 구분합니다. 트리 화면은 관계와 BFS/DFS 탐색으로 바로 열립니다.

처음에는 기본 예제를 바로 관찰할 수 있도록 설정이 접혀 있습니다. **예제·설정**에서 입력과 방법을 바꾸고 **설정 닫기**로 돌아옵니다. 넓은 화면에서는 큰 시각화와 선택한 정보 탭을 나란히 표시하며, 900px 이하에서는 시각화를 포함한 여섯 탭 중 하나를 보여 줍니다. **모두 펼치기**로 여섯 영역을 함께 확인하고 **간단히 보기**로 돌아올 수 있습니다. **예상해 보기**에서 다음 상태에 관한 질문을 확인합니다.

패널은 내용 높이만큼 펼쳐지고 페이지 전체를 세로로 스크롤합니다. 가로로 긴 코드·표·구조는 내부 가로 스크롤을 유지합니다. 실행 기록은 최근 8개를 먼저 보여 주며 ‘이전 기록 N개 펼치기’로 전체 기록을 확인할 수 있습니다. 하단 재생 바 높이에 맞춰 마지막 내용 아래에 여백을 둡니다.

탭의 방향키·Home·End는 영역 선택만 바꾸며 실행 단계와 재생 상태는 유지합니다. 비교 카드의 단계 보기와 과정 전환은 선택한 코드에 포커스를 옮깁니다. 자세한 동작은 [관찰 화면](docs/OBSERVATION.md), 시각 기준은 [DESIGN.md](DESIGN.md)에 기록했습니다.

### 함수와 재귀

1. **예제·설정**을 열어 n을 입력하고 **입력 적용**을 누릅니다. 입력을 수정하는 순간 기존 기록이 초기화됩니다.
2. 먼저 다음 상태를 예상한 뒤 **다음**으로 한 사건씩 진행합니다.
3. **이전**, 기록 버튼, 단계 슬라이더로 과거 스냅샷을 확인합니다. 수동 이동은 자동 실행을 멈춥니다.
4. **자동 실행** 중에도 일시 정지·입력 변경·속도 조절이 가능합니다. 끝에서는 자동으로 멈춥니다.
5. 입력창·버튼 등 조작 요소 밖에서 `←`/`→`로 이전·다음, `Space`로 자동 실행·정지를 제어합니다. `Tab`으로 모든 버튼과 스크롤 영역에 접근합니다.

기본 최대 160단계(초기·종료 포함), 동시 프레임 13개, 입력 n=0~12로 제한합니다. 호출 트리는 최대 13개 노드이며 스크롤로 탐색할 수 있습니다. 최대 입력은 79개의 스냅샷을 생성하므로 동기 생성으로 제한된 작업량을 보장합니다. 향후 큰 입력을 다루는 모듈은 Worker 또는 중단 가능한 청크 실행이 필요합니다.

함수 영역의 **예제 선택**에서 일반 함수, 팩토리얼, 피보나치를 고를 수 있습니다. 합·팩토리얼·일반 함수는 n=0–12, 피보나치는 F₀=0·F₁=1 정의로 n=0–8입니다. **같은 입력으로 재귀·반복 비교**를 열고 **재귀/반복 단계 보기**를 누르면 각 방식에서 보던 위치로 돌아갑니다. 피보나치는 n−2를 먼저 호출하며, 완료 가지 접기는 실제 계산을 생략하지 않습니다. 새 예제는 기본 안전 한도 500단계·깊이 13을 적용합니다. [함수 실습 계약](docs/FUNCTIONS.md)에 자세한 동작과 집계를 기록했습니다.

### 큐와 스택

삽입에 성공하면 입력창을 비우고 포커스를 돌려줍니다. 코드는 삽입·삭제 두 조각으로 고정되며, 요청을 추가해도 길어지지 않습니다. 현재 입력 `item`과 코드 강조는 관찰 중인 단계에 맞춰 바뀝니다.

1. 상단 메뉴에서 **큐와 스택**을 선택합니다. **예제·설정**의 자료구조 선택에서 큐 또는 스택을 고릅니다.
2. **직접 조작**에서는 −99~99의 정수를 삽입하거나 삭제합니다. 0과 중복값을 허용합니다.
3. 조작 결과로 바로 이동한 뒤 **이전**으로 조건 검사와 연산 전 상태를 관찰합니다. 지난 기록에서는 **마지막 단계로** 돌아와 새 연산을 추가합니다.
4. **예제 실행**에서는 1, 2, 3, 4를 삽입하고 네 번 삭제하는 같은 연산을 큐·스택에서 각각 관찰합니다. 은행 대기열과 객차 순서 활동으로 연결합니다.
5. 구조·실습 방식·학습 공간 변경과 **새 실습**은 기존 기록과 타이머를 초기화합니다. 직접 조작의 ‘삽입할 값’ 수정은 다음 명령의 인수만 바꾸며 기존 구조와 기록을 유지하고 재생을 멈춥니다.

**최대 용량**에서 1~12개를 선택할 수 있으며 기본은 6개입니다. 용량을 바꾸면 실행·자료구조·기록을 초기화하고, 선택한 용량은 직접 조작과 예제 실행에 함께 적용됩니다. 직접 조작은 최대 40회입니다. 거절된 요청도 조작 횟수에 포함합니다. 한도를 채우면 새 실습으로 다시 시작합니다. 공통 실행 한도는 100단계이며 최대 40회 직접 조작은 81개 스냅샷을 만듭니다. 형식이 잘못된 삽입값은 실행 전 안내하며 기록을 추가하지 않습니다.

포인터는 0부터 센 **논리적 위치**입니다. 큐의 Front는 첫 원소, Rear는 마지막 원소를 가리키고, 스택 Top은 마지막 원소를 가리킵니다. 빈 구조의 포인터는 ‘없음’입니다. 큐 그림의 재배치는 실제 메모리 복사나 순환 큐의 주소 이동을 나타내지 않습니다. 자세한 규칙은 [큐·스택 실습 계약](docs/LINEAR_STRUCTURES.md)에 기록했습니다.

### 그래프·트리와 BFS/DFS

1. **그래프와 탐색** 또는 **트리와 탐색**을 선택합니다. 기본 예제부터 바로 재생할 수 있습니다.
2. **예제·설정 → 그림·연결 편집**에서 그림의 정점을 끌어 배치하고 빈 곳에 추가하거나 두 정점을 연결·해제합니다. 정점 삭제와 간선 클릭 삭제도 가능하며 행렬·리스트에 바로 반영합니다. 기존 문자·선택 입력도 함께 사용할 수 있습니다.
3. 문자 입력은 **표현 적용**으로 검증하고 **탐색 준비**를 누릅니다. 모든 입력 변경은 이전 실행과 비교 기록을 지웁니다.
4. **다음/이전**으로 큐·재귀 프레임·발견 기록을 관찰하고, 정점을 선택해 관계와 발견 경로를 확인합니다.
5. **BFS·DFS 결과 비교**로 같은 입력의 독립된 최종 기록을 비교합니다. **BFS/DFS 단계 보기**와 **BFS/DFS 과정**으로 전환하면 각 탐색에서 보던 위치를 복원합니다. BFS의 최단 경로는 모든 간선 비용이 1이라는 전제이며 DFS는 최단을 보장하지 않습니다.

정점 1–8개(A–Z), 자기 루프·중복 간선 없음, 문자 입력 1,024자, 최대 500단계입니다. 트리는 부모→자식 방향을 검증하며 이진 배열은 루트 1, 자식 2i·2i+1입니다. 첫 자식을 왼쪽으로 두고, 하나뿐인 자식도 왼쪽으로 둡니다. 시작점에서 닿는 영역을 끝까지 탐색하며 목표 발견만으로 멈추지 않습니다. 자세한 내용은 [그래프·트리 탐색 계약](docs/GRAPH_TRAVERSAL.md)을 참고하세요.

### 미로에서 BFS/DFS 비교

**그래프와 탐색 → 미로 BFS·DFS**를 선택합니다. 기본 9×13 미로 두 개가 넓게 나타납니다. 칸을 클릭하면 벽을 켜고 끄며, 끌기는 첫 칸이 길이면 벽 생성, 벽이면 삭제로 끝까지 유지됩니다. S(출발)·G(도착)는 끌어서 놓은 칸으로 옮깁니다. 어느 그림에서 편집해도 양쪽에 같이 반영됩니다. **편집 되돌리기 / 편집 다시하기**는 드래그 한 번을 한 작업으로 묶고 최근 50개 작업을 복원합니다. Ctrl+Z / Ctrl+Shift+Z도 지원하며, 벽 전체 지우기·예제 변경도 되돌릴 수 있습니다.

**같이 탐색**, **일시 정지**, **한 칸씩**, **이전**, **결과 비교**, **처음으로**로 두 탐색을 함께 관찰합니다. 사용자 요청에 따라 미로는 코드·상세 패널 없이 발견한 칸 수와 경로 길이만 비교하는 전용 화면입니다. 기본 예제는 BFS 59칸 발견·12회 이동, DFS 21칸 발견·20회 이동입니다. 기존 작은 갈림길 예제(5×7)의 BFS 18칸·6회 이동, DFS 11칸·10회 이동도 유지합니다. 편집 되돌리기와 탐색 단계의 ‘이전’은 별개이며, 편집을 바꾸면 양쪽 탐색 기록을 초기화합니다.

최대 15×21칸, 상하좌우 이동 비용 1입니다. 기록은 Worker에서 준비하며 중단할 수 있습니다. 공통 탐색 실행기의 발견 장면만 저장해 최대 격자도 알고리즘당 317개 이하 스냅샷으로 비교합니다. 별도로 실행 사건 50,000회와 저장 단계 2,000개의 안전 한도를 둡니다. 출구를 먼저 찾은 쪽은 그 경로와 지표를 유지합니다. 재생 속도는 실제 계산 속도를 뜻하지 않습니다. 작은 화면은 두 그림을 위아래로 배치하며 더 큰 칸으로 편집하려면 5×7 또는 7×7 예제를 선택할 수 있습니다. [미로 활동 계약](docs/MAZE.md)에 비교 기준·한도와 예제 추가 방법을 기록했습니다.

교과서 재현 코드와의 차이 및 현재 한계는 [출처 기록](docs/SOURCES.md)과 [개발 계획](docs/ROADMAP.md)을 참고하세요.
